### Diff-scope review (adversarial / edge-case / verification-gap lenses, re-verified at source)

- **V1 — `validatePlan`'s two new admission rules are unpinned by any test.** `orchestrator/orchestrator.ts:334` ("has no steps") and `:341` (givenStateId ≠ first-step stateId) run pre-launch at `:62` but no `*.test.ts` imports `validatePlan`; `orchestrator.test.ts` sets `scenario.route` (:672, :774) but never `givenStateId`, so the mismatch branch is dead in CI. Consequence (from `smoke.test-plan.ts:88` `givenStateId: "orderBook"`): a drifted givenStateId would bootstrap the browser to one screen (:147-167) while steps drive transitions from `steps[0].stateId` (:172-212) — action from the wrong screen recording false snapshot evidence; a stepless scenario would crash at `scenario.steps[0]!` (:147) after the browser opens. **Disposition: fix now** (plan-admission tests).
- **V2 — `bin/run-smoke.ts` operator surface unpinned at process level.** Only its selection logic is tested (`bin/scenario-select.test.ts`); sibling operator surfaces are process-tested (`orchestrator/handlinks.test.ts` spawns the corpus CLIs, `bin/validate-smoke.test.ts:391` spawns `validate:smoke`). The new run-smoke behavior (handoff-last ordering `:95-134`, zero-scenario/modelVersion guard `:106-114`, all-failed guard `:116-124`) ships unverified. **Disposition: fix now (consolidated with the 5-3 defer below)** — one testable rule: pin the operator CLIs at process level, including a `validate:smoke` 18/18 regression pin (the 5-3 review defer).
- **E1 — bootstrap stepIndex reuse after a failed recovery/bootstrap.** `orchestrator.ts:204-207` increments the index only on success; after a failed bootstrap loop or a failed `recoverToHome` (`:131-142`), the next re-bootstrap/recovery reuses the same index, so the manifest can carry two `BootstrapRecord`/`StepFailure` entries sharing one `stepIndex`. Evidence *filenames* escape collision (stems embed `scenarioId` for the bootstrap phase, `:647`) but any manifest consumer keyed on `stepIndex` mislinks. **Disposition: defer** (recorded with evidence).
- **E2 — zero-step bootstrap leaves no `setupResults` entry.** `orchestrator.ts:213-215`: a scenario already at its givenStateId pushes nothing, so reporters summing `setupResults` undercount. **Disposition: accept** (by design; nothing surfaces it today).
- **E3 — `evaluate()` switch lacks a `default:` case.** `validators/validator-map.ts` — pre-existing; already tracked verbatim as a 5-3 review defer in `deferred-work.md` (2026-09-10). **Disposition: already tracked — no new action.**
- **E4 — `testPlanSchema` allows an empty `steps` array.** Zod-admitted, caught later by `validatePlan` (`:334`). Harmless unless the schema is parsed directly. **Disposition: accept** (validatePlan owns admission); folds into V1's positive/negative tests.
- **E5 — (adversarial #1) REFUTED at source.** `currentStateId = givenStateId` is set at `orchestrator.ts:212` even when `bootstrapPath` is empty, so the claimed "never assigned" is false. **Dropped — no source.**
- **A6 — `navigateHome` is contract-valid from `homePage` but the FSM has no `homePage→homePage` self-loop.** `model/fsm.ts` transitions run `navigateHome` from the dialog/history/portfolio states, not homePage. Harmless today: `Given:navigateHome` resolves to `givenStateId === homePage` (empty path) and `recoverToHome` is a direct `page.goto`, never a plan step. **Disposition: accept** (documented non-issue).
- **A7 — empty corpus run folder created even for a zero-scenario plan.** `startCorpusRun()` at `orchestrator.ts:96` precedes the scenario loop. **Disposition: accept** (validatePlan keeps this unreachable in practice).
- **A8 — emitted repro carries its own BFS mirroring `resolveBootstrapPath`.** `repro/repro-generator.ts:119-137` bakes a queue-based planner into the emitted script. Deliberate (the repro must be self-contained) but drift-prone if path semantics change. **Disposition: accept** (design mirror; note for the FR-12/13 wiring work).
- **A9 — step error strings unbound in size.** Step failures record raw action errors; no truncation cap observed. **Disposition: accept** (failure evidence is now artifact-separated per step).
