## Findings

### Aggregate views

**A1 — Architecture delta: clean.** `validators/cross-view.ts` imports only `model/` + `validators/corpus-loader.ts` (layer rule preserved: validators/ never imports orchestrator/; the test file's fixture import of `orchestrator/corpus.js` matches the established `offline-runner.test.ts` pattern). `repro/repro-generator.ts` imports `model/` + `orchestrator/action-map.js` (the permitted repro/ direction) and no runtime modules. No cycles. **Disposition:** accept.

**A2 — Third model-resolution implementation (duplication family).** `repro/repro-generator.ts` `validatePath` builds state/contract/transition/actionMap indexes and throws on the first gap — a third hand-rolled model-resolution path alongside `model/ssot-guard.ts` and `orchestrator/orchestrator.ts` `validatePlan`. It differs from the other two: it validates a flat `ScenarioStep[]` (not a `TestPlan`), checks `allContracts` separately, and — unlike the orchestrator's `validatePlan` (`orchestrator.ts:219-239`) — does **not** check path continuity (next step's `stateId` must equal the previous transition's `to`). This is the same duplication family as epic-3 F3/item-8 (plan-walk + model-resolution logic in multiple sites). **Disposition:** defer, fold into the open plan-step/model-resolution consolidation (epic-3 item-8); the continuity gap itself is F2 below.

**A3 — God-class / size growth: none.** Production files are small (`cross-view.ts` 249, `repro-generator.ts` 224); test:production ratios are healthy (cross-view ~1.66:1, repro ~0.71:1). No file approaches a god-class. **Disposition:** accept.

**A4 — Pattern divergence: minimal, one real one.** Validators convention is "failures are results, never throws" (`validator-map.ts:1-7`; `offline-runner.ts:21-23` catches validator throws). `cross-view.ts` throws at entry for declaration gaps (empty/duplicate surfaces, duplicate ids, unmodeled surface) — this is spec'd (4.2 matrix UNMODELED_SURFACE "throws at entry") and confined to declaration-time, so it is a deliberate, documented deviation. **But** `checkInvariant` calls `invariant.normalize` without an exception boundary (`cross-view.ts:181-190`), so a throwing normalizer aborts the whole run — violating the result-never-throw convention at *run* time (F4 below). Minor: `crossViewInvariants` is a mutable exported array that tests push/pop (`cross-view.test.ts:441, 524`) — diverges from the immutable-first style, acceptable for a registry but worth noting. **Disposition:** accept the entry-time throws and mutable registry; fix the normalize boundary (F4).

**A5 — Spec-to-implementation reconciliation: on-track, one gap.** Both stories implement their declared ACs; the added declaration-gap checks (empty/duplicate surfaces, duplicate ids) exceed the 4.2 matrix's minimum and are tested. The one reconciliation gap is the repro **path-continuity** check the orchestrator has but the generator omits (F2). Also: cross-view `corpusRefs` name `probe:<name>@<stepIndex>` but never the surface/stateId — a divergence details message names surfaces, but refs do not; spec only required surfaces named in `details`, so this is a cosmetic enhancement, not a violation. **Disposition:** accept; continuity gap is F2.

### Diff-scope review (bmad-review code lenses: adversarial, edge-case-hunter, verification-gap)

**F1 — Repro path continuity not validated (generation-time or runtime).** `repro-generator.ts:188-223` checks each step's (state, contract) is a declared transition but never that `step[i+1].stateId === transition.to`; the emitted runtime guard (`repro-generator.ts:772-787`) repeats the same per-step checks without continuity. A disjoint-but-individually-valid path emits a repro that cannot execute as written. The orchestrator's `validatePlan` DOES enforce continuity (`orchestrator.ts:231-238`), so the generator is the odd one out. **This is the boundary no single story could see: 4.1's review deferred it as a spec question (`deferred-work.md:106-108`), and the epic view confirms it.** **Disposition:** **propose fix now** (see Action item 1) — add continuity validation to `validatePath` + the emitted runtime guard; requires the human's decision on whether "reproduces the failure" includes whole-path runnability.

**F2 — Emitted repro has no timeout discipline (hang risk).** `page.goto(BASE_URL)` (`repro-generator.ts:101`) is called with no timeout, and each `action({ page })` (`:130`) is awaited without a timeout wrapper; `STEP_TIMEOUT_MS` only bounds the settle wait. A hung navigation or action leaves the repro hanging indefinitely — unlike the orchestrator, which wraps action+settle in `withTimeout` (`orchestrator.ts:292-294`). **Disposition:** **propose fix now** (Action item 2).

**F3 — Cross-view validators are library-only: nothing calls them, and their probe is never collected.** `runCrossViewInvariants` (`cross-view.ts:74`) is not composed into `runValidatorsOffline`, `validatorMap`, or any entry point; `dependencies.ts`/`requiredProbeNames` derive probe deps only from contract predicates, so a run plans no `portfolio-value` probe for the seed invariant. Behavior check confirms: over a real recorded corpus the seed invariant fails as missing evidence — honest, but the feature cannot pass on any real corpus until wired. **Already tracked** in `deferred-work.md` (4.2 review). **Disposition:** defer (tracked); propose the wiring decision in Action item 5.

**F4 — Cross-view normalize has no exception boundary; a throwing normalizer aborts the run.** `checkInvariant` calls `invariant.normalize(observation.value)` (`cross-view.ts:181-190`) bare; `offline-runner.ts` would catch a throwing *validator*, but `runCrossViewInvariants` is called outside that wrapper. One malformed registry entry or a value that trips the normalizer kills every invariant for the run. Related edge case (edge-case-hunter): a non-empty raw value that normalizes to `""` for all surfaces passes vacuously (`normalizedValues.every(... === normalizedValues[0])`). **Disposition:** **propose fix now** (Action item 3) — wrap `normalize` in a try/catch returning a failed result naming the invariant+surface, and treat normalized-empty as missing evidence.

**F5 — Registry declaration validation is incomplete.** `cross-view.ts:93-125` validates surfaces and ids but not `probeName`/`fact` non-empty; an empty `invariantId` or `probeName` is accepted and emits an unusable result or permanent missing evidence with no declaration-time diagnostic. **Disposition:** **propose fix now** (fold into Action item 3 — same entry-time `assertRegistryEntryGaps`).

**F6 — CapturedAt ordering: accepted.** `latestObservation` compares `capturedAt` as a raw string (`cross-view.ts:226-228`) and ties keep first-in-plan-order (deterministic). Collectors always stamp `new Date().toISOString()` (canonical, lexicographically sortable), and the corpus schema validates the field is a string, so the risk is theoretical. A defensive `Date.parse` guard is cheap but not needed today. **Disposition:** accept (recorded); note the tie rule is deliberately deterministic.

**F7 — Equal-`capturedAt` tie rule is untested (verification gap).** `cross-view.test.ts:209-248` tests latest-observation ordering only with distinct timestamps; the documented "ties keep first plan-order" behavior has no test, so a `>` → `>=` regression would pass. **Disposition:** accept as a minor gap — propose a small test add in Action item 3's sweep.

**F8 — Latest-observation scope is corpus-global per surface, not scenario-scoped.** `checkInvariant` compares the latest observation of each surface across the whole run regardless of scenario or temporal segment. Two observations of the same surface from different scenarios/times can be compared, and an earlier-scenario divergence can be masked by a later observation. This matches the 4.2 spec's design ("latest recorded observation per surface") and is deterministic — but a fact that legitimately changes mid-run (portfolio value ticking) can produce a spurious divergence, and the "comparison instant" is implicit. **Disposition:** accept as spec'd, but record as an open question (comparison scope semantics) for the wiring story.

**F9 — Missing-surface corpusRefs give no step/probe location.** `cross-view.ts:163-177` includes refs only for *observed* surfaces; a missing surface's failure names the surface + reason but no step index to open. `details` already carries the reason and the surface name, so this is cosmetic. **Disposition:** accept.

**F10 — Emitted repro is never executed in tests (verification gap).** `repro-generator.test.ts` asserts generated source text only (imports, guards, ordering, determinism); nothing compiles-or-executes the emitted script, so a template/runtime regression ships green. The 4.1 deferred-work already records the typecheck-gate gap (`deferred-work.md:118-120`); the execute-with-mocks gap is its stronger sibling. **Disposition:** defer — fold into the existing deferred typecheck-gate item; propose in Action item 4.

**F11 — Cross-view has no real-orchestrator round-trip test (verification gap).** `cross-view.test.ts` hand-writes corpus files; nothing drives `runTestPlan` then `runCrossViewInvariants` over the resulting real corpus layout. The 4.2 deferred-work records the wiring gap (`deferred-work.md:122-125`); a round-trip test is its companion and becomes meaningful only once wiring exists. **Disposition:** defer (tracked with F3).

**F12 — Write destination is CWD-relative.** `writeReproScript` resolves `scripts/` against the process working directory (`repro-generator.ts:167`), so invoking from another directory writes the repro outside the repo while returning a misleading repo-relative path. Tests run from the repo root. **Disposition:** accept as documented behavior; note if a CLI story lands.
