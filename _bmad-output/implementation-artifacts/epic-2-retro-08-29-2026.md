## Findings

### Spec-to-Implementation Reconciliation

**F1 — The contract `action` field is dead weight; the real binding is `actionMap`**
- **Source:** `model/contracts.ts:6-29` declares `action: ContractAction` and `placeholder`; every seeded contract sets `action: placeholder`. A search for `.action` finds **no reader** — the runtime dispatch is `actionMap[step.contractId]` at `orchestrator/orchestrator.ts:216`. The vision doc `project-context.md:84-92` even shows `action` as inline lambdas, which the implementation deliberately moved out of the model (the `actionMap` lives outside the `modelVersion` hash boundary).
- **Verdict:** The `action` *field* and `placeholder` are vestigial; only the `ContractAction` *type* is used (by `action-map.ts`). The field misleads — it implies a contract carries its own behavior when it doesn't.
- **Disposition:** Defer (cleanup). Drop `action` from `DialogContract` and delete `placeholder`; keep `ContractAction`.

**F2 — Story 2-4 left `smoke.test-plan.ts` modelVersion stale (caught late, no unit guard)**
- **Source:** 2-4 (`eafb25e`) changed `model/schemas.ts` (git_evidence: +177 net over 9 commits) but did not regenerate `model/smoke.test-plan.ts`; the plan kept `b96a1b8c…` until 2-6 regenerated it (`f6de3e36…`, then `049d5e66…` after `settleSelector`). Documented in `spec-2-6` change log.
- **Verdict:** The guard that *should* catch this (`orchestrator.ts:48`, `modelVersion !== computeModelVersion()`) only fires at runtime. No unit test asserts the plan hash against the real model files — `computeModelVersion` is mocked in `orchestrator.test.ts:6`, and there is no `model-version.test.ts`.
- **Disposition:** **Fix now** — add a test that asserts `smokeTestPlan.modelVersion === computeModelVersion()` against the committed model files, so a schema change that forgets to bump the plan fails CI instead of the smoke run.

**F3 — `settleSelector` added without an architecture note (accepted extension)**
- **Source:** `model/schemas.ts:204-209` + `orchestrator/orchestrator.ts:221`, introduced in 2-6 to fix the post-step settle using the home-only hero selector.
- **Verdict:** Reasonable extension consistent with AD-13's config-threading; not in `epic-2-context.md`'s Technical Decisions.
- **Disposition:** Accept. Optionally note it in the architecture spine next time it's touched.
