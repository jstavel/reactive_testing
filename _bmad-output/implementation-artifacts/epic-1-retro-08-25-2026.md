## Findings

### Spec-to-Implementation Reconciliation

**F1 — Story 1.2 scope deviation: Home Page instead of History/Main/Ledger**
- **Source:** `epics.md:136` (declared: "History/Main/Ledger with filter-by-type, paginate, clear-filters") vs `model/fsm.ts:41-57` (actual: Home Page states — homePage, portfolioSummaryDialog, historyMain/Futures, portfolioOverview/Main/Futures/Loans, earn)
- **Verdict:** Accept as-is. The spec left "other surfaces" as Open Questions. Home Page is the natural entry point and a valid critical path. The declared History/Main/Ledger contracts (filter-by-type, paginate, clear-filters) are absent from the seed — they can be added when History pages are modeled.
- **Disposition:** Accept. No action needed.

**F2 — Layout menu scenarios exist but have no model counterpart**
- **Source:** `features/home-page-layout-menu.feature` (2 scenarios) vs `model/fsm.ts` / `model/contracts.ts` (no layout-related state or contract)
- **Verdict:** Genuine gap. The layout menu toggle is tested in Gherkin but not represented in the model. This violates the "model is SSOT" principle — the model should contain everything the scenarios test.
- **Disposition:** Defer. The layout menu is a simple toggle; it could be added as a contract (`clickLayoutMenu`) in a future model update. Not blocking for Epic 1 acceptance.

**F3 — Portfolio value cross-surface invariant not modeled**
- **Source:** `features/home-page-portfolio-value.feature` ("Current portfolio value agrees across Home surfaces") vs `model/contracts.ts` (no cross-view invariant contract)
- **Verdict:** Expected gap. Cross-view invariants are Epic 4 territory (FR-13). The scenario is correct as a smoke check; the model doesn't need a contract for it yet.
- **Disposition:** Accept. Epic 4 will address this.

**F4 — Stories 1.3–1.5 produced no code changes**
- **Source:** Commits `7567a07` (1.3), `bee358d` (1.4), `5415381` (1.5) — all 3 commits touch only `_bmad-output/` artifacts, no model files
- **Verdict:** Valid. These stories are workflow capabilities (discovery process, dedup workflow, adjudication gate). The review session in Story 1.3 produced 7 proposals, all deferred as out of scope. The stories establish the *process* for future model growth, not immediate data additions.
- **Disposition:** Accept. The workflow is now documented and executable.

**F5 — Test plan generation is manual, not regenerable**
- **Source:** `model/smoke.test-plan.ts` (static file) vs `epics.md:188` ("the AI generates or updates the plan file")
- **Verdict:** Acceptable for v1. The spec says "generates or updates" — the current file can be regenerated by re-running the tagging workflow. A CLI tool for automatic regeneration would be a nice-to-have but is not required for Epic 1.
- **Disposition:** Defer. Epic 2 can add tooling if needed.
