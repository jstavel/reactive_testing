- (decision) AD-1: Model is the SSOT — one FSM graph per application, split into fsm.ts, contracts.ts, schemas.ts. Gherkin is the input interface, never the SSOT. Prevents: truth living in Gherkin or test code instead of the Model.
- (decision) AD-2: Corpus is runtime data (snapshots, network events, DOM probes, screenshots) — distinct from the Model. The Model is what the app IS; the Corpus is evidence of what it did. Prevents: conflating spec truth with runtime observation.
- (decision) AD-3: Validators are per-contract, pure functions (corpus → pass/fail), separate from the Model. Types: contract-level for MVP; cross-state invariants and other types emerge from implementation. Prevents: mixing app definition with test verification.
- (decision) AD-4: Orchestrator is offline and deterministic — no AI in the runtime loop. Input is a Test Plan (TypeScript file): path (FSM states), collection (what data), validators (what to run). Orchestrator drives browser, passes page to Collectors, triggers Validators. Prevents: non-deterministic AI-driven test execution.
- (decision) AD-5: Collectors are multiple specialized units (SnapshotCollector, NetworkCollector, ScreenshotCollector, etc.). Option B: Orchestrator passes page object to Collector, Collector captures data (page in → corpus data out). MVP scope: snapshots, network events, DOM probes, screenshots. Prevents: monolithic collector that's hard to extend or test.
- (decision) AD-6: Validator declares what corpus data it needs. Orchestrator reads these declarations to plan which Collectors to run. Prevents: unnecessary data collection and missing required data for validation.
- (decision) AD-7: Repro Generator emits standalone Playwright scripts from the Model. Input: bug path (FSM states). Output: simple, readable script for manual developer validation — no validations, no framework dependency. Reads: Model (FSM states + transitions). Prevents: developers having to manually reconstruct bug reproduction steps.
- (decision) AD-8: Reporter is separate from Orchestrator — different reason to change. Produces human-readable reports (with screenshots) and CI/CD formats (xunit XML, JSON). Reads: Corpus (including screenshots). Prevents: coupling orchestration logic with output formatting.
- (decision) AD-9: Gherkin Interface is a file convention (.feature files) with no processing layer. AI Agent (OpenCode/MCP) reads Gherkin directly and translates into Model updates + Test Plans. Primary role: input (Jan describes use cases). Secondary role: output (failing tests surface as Gherkin for review). Prevents: unnecessary middleware between human input and AI interpretation.
- (decision) AD-10: AI Agent is OpenCode/MCP — the pair programmer. Reads Gherkin, queries Model for delta, proposes Model updates, generates Test Plans, writes code. Jan reviews all changes via emacs/magit. Prevents: unreviewed AI changes to the Model.
- (decision) AD-11: Graph Query Engine is deferred (RFC/nice-to-have). Natural application of MBT — querying the Model for consistency, cognitive load, missing edges — but not critical for MVP. Revisit when Model is mature enough. Prevents: premature optimization of model queries before the model exists.
- (decision) AD-12: Dedup for Model updates — real concern with human Gherkin input. Programmatic delta query deferred (RFE). For now, AI Agent checks for duplicates during conversation. Prevents: duplicate states/contracts accumulating in the Model.
- (constraint) TypeScript is the only language for Model, Test Plans, Validators, Repro scripts. No YAML, no other languages. Type safety is the contract.
- (constraint) v1 scope: read-only flows only (order History, order book, portfolio). No order execution, no mutating contracts. Deferred to later phase with real-money DCA buys.
- (constraint) One format per file. Snapshots live in separate plain-data files, never embedded in TS code. Model in TS, runtime data as plain data.
- (assumption) Browser automation: Playwright over CDP against live authenticated Kraken Pro app (read-only). AI Agent reads DOM/aria snapshots via Playwright MCP.
