topic: Story 2.1: Orchestrator executes a test plan deterministically
updated: 2026-08-26T22:37

- (direction) Scope: orchestrator reads test plan, verifies modelVersion, drives browser through declared path via Playwright. No collectors, no corpus writing, no validators — those are Stories 2-2 through 2-4.
- (decision) TestPlan schema needs per-scenario path expansion (steps: stateId + contractId) for the orchestrator to execute. Current schema has planId/modelVersion/scenarioIds only.
- (decision) ContractAction remains abstract in this story — orchestrator maps contractId to Playwright page calls via a lookup, replacing the placeholder actions in contracts.ts.
- (constraint) No AI calls during execution (AD-4). modelVersion must match before execution (AD-17). TypeScript only, tsc --noEmit clean.
- (constraint) No order-execution or mutating contracts (NFR-3). Read-only flows only in v1.
- (capability) CAP-1: The orchestrator reads a generated test plan and executes the declared path through the FSM states, driving the browser deterministically with no AI in the loop.
- (capability) CAP-2: The orchestrator verifies modelVersion (SHA-256 of fsm.ts + contracts.ts + schemas.ts) matches the current model before execution, aborting with a clear error on mismatch.
- (capability) CAP-3: The orchestrator provides a Playwright Page to each step's contract action, replacing the placeholder actions with real browser interactions.
- (capability) CAP-4: The orchestrator manages the Playwright browser lifecycle (launch, connect, close) for a test plan run.
- (note) Playwright is now a devDependency (added during Epic 1 scaffolding or will be added for this story). Node 24.19.0, TypeScript 5.9.3.
- (event) SPEC.md derived from memlog. 4 capabilities, 6 constraints, 5 non-goals, 2 open questions.
- (event) Self-validate Pass 1 (Coherence): PASS — all 4 capabilities have intent+success, constraints bend design, non-goals explicit, success signal concrete.
- (event) Self-validate Pass 2 (Preservation): PASS — AD-4, AD-17, NFR-3, NFR-4 all preserved. Collectors/corpus/validators explicitly out of scope (non-goals).
- (decision) Per-scenario path embedded in TestPlan schema (option 1). No separate scenario files.
- (decision) ContractId → Playwright action resolved via a static lookup map. Orchestrator imports a map of contractId → (page) => Promise<void> and calls it for each step.
- (decision) Orchestrator public API: exported function runTestPlan(plan: TestPlan, config: OrchestratorConfig): Promise<RunResult>. Params: TestPlan (expanded) + config. Return: RunResult with pass/fail per scenario.
- (decision) Static lookup map lives in orchestrator/action-map.ts. Exports: Record<string, (context: { page: Page }) => Promise<void>>. One canonical file; downstream stories import from there.
- (decision) Initial-state bootstrapping: orchestrator navigates to config.baseUrl, waits for a configurable readySelector (default: main navigation visible), verifies FSM initialStateId is reached before executing steps.
- (decision) TestPlan schema expansion: scenarios field replaces scenarioIds. Shape: scenarios: Array<{ id: string, steps: Array<{ stateId: string, contractId: string }> }>. planId and modelVersion remain.
- (decision) Configuration via OrchestratorConfig type: baseUrl (string), headless (boolean, default true), readySelector (string), stepTimeout (number ms, default 30000), runTimeout (number ms, default 300000). Exported from schemas.ts.
- (decision) File structure: orchestrator/orchestrator.ts (core logic), orchestrator/action-map.ts (contractId to Playwright lookup), orchestrator/browser.ts (lifecycle). Imports from model/.
- (decision) ContractAction context type widened from (context: unknown) to (context: { page: Page }) => Promise<void>. This story updates contracts.ts signature.
- (decision) Failure propagation: step-level timeout (config.stepTimeout). On step failure, abort current scenario, record error, continue with next scenario. Run-level timeout (config.runTimeout) aborts entire run.
- (decision) Hash computation: read fsm.ts, contracts.ts, schemas.ts as UTF-8 LF-normalized, concatenate in alphabetical filename order, SHA-256 hex digest. Pinned algorithm; same on all platforms.
- (decision) Invariant-checking scenarios (no contractId, declarative only) are excluded from orchestrator execution scope. The orchestrator only executes scenarios with steps containing contractId. Invariant scenarios are verified by Epic 3 validators.
- (decision) Post-action settling: after each contract action, orchestrator waits for the target state's expected URL pattern (from FSM state definition) or a configurable settlingSelector. Default: URL match.
- (decision) Pre-execution validation: orchestrator validates test plan structure (Zod parse), verifies all step stateIds exist in FSM, verifies all step contractIds exist in lookup map, verifies steps form valid FSM path from initialStateId. Fails fast with descriptive error.
- (decision) Test strategy: unit tests with mocked Playwright for orchestrator logic; integration test against a minimal local HTML fixture that models a simplified FSM (3 states, 3 transitions). Live Kraken Pro testing is manual acceptance.
